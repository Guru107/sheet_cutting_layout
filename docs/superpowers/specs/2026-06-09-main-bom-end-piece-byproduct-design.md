# Main BOM End-Piece Byproduct Design

## Context

When a released sheet cutting layout has a reusable end piece, that end piece is a byproduct of
the main BOM. Today the main BOM includes the raw material sheet, finished-part process scrap, and
end pieces marked as scrap, but it does not include reusable end pieces in the BOM scrap table.

For layout `002-R2`, generated BOM `BOM-FG01SHR-004` consumes `RM001 = 39.3 Kg` and creates
`77 Nos` of `FG01SHR`. The BOM scrap table contains only `MSScrap = 14.233142 Kg`. The layout also
has a reusable end piece weighing `2.81388 Kg`, so the BOM has an unreconciled shortfall:

```text
39.3 - (77 * 0.289) - 14.233142 = 2.813858
```

The main BOM should reconcile to the input raw material sheet weight.

## Scope

This change applies to main BOMs generated by this app during layout release.

It does not change the separate end-piece BOM generation flow except that the flow should reuse
any generated end-piece Item already created during release.

## Behavior

During MR Release, main BOM creation should handle each `Reuse` row in `end_pieces` as a BOM
byproduct:

- Ensure the generated end-piece Item exists before the main BOM is inserted.
- Use the same deterministic item-code derivation and Item defaults used by end-piece BOM
  generation.
- Store the generated Item code on the layout end-piece row.
- Append a BOM Scrap Item row for the reusable end piece.
- Use the generated end-piece Item as the scrap-row `item_code`.
- Use `row.weight_kg` as the scrap-row quantity.
- Use `Kg` as the stock UOM.
- Resolve rate from the generated end-piece Item valuation, which is copied from the source raw
  material Item.

Rows with `disposition = "Scrap"` should keep the existing behavior: they use the selected
`scrap_item` as the BOM scrap row. Process scrap should keep using `layout.process_scrap_item`.

The main BOM mass balance should be validated against the input raw material sheet weight:

```text
raw_material_weight_kg =
  finished_part_quantity * net_weight_per_part_kg
  + process_scrap_weight_kg
  + scrap_end_piece_weight_kg
  + reusable_end_piece_byproduct_weight_kg
```

For `002-R2`, the expected balance is:

```text
39.3 = (77 * 0.289) + 14.233142 + 2.81388
```

Small decimal differences should be compared using the app's existing precision/tolerance style
rather than exact floating-point equality.

## Trade-Offs

Creating reusable end-piece Items during MR Release adds record creation to the release path, but
it makes the generated main BOM complete immediately and prevents a material shortfall in ERPNext.

Requiring the end-piece Item to exist before release would keep release simpler, but it would make
MR Release depend on a separate user action and would fail for normal layouts like `002-R2`.

Keeping reusable end pieces only in validation would be the smallest code change, but the submitted
ERPNext BOM would still be materially incomplete.

Adding reusable end-piece rows to `bom.scrap_items` means summary fields that sum all scrap rows,
such as layout finished-part scrap references, represent total byproduct/scrap weight rather than
only process scrap. That is acceptable because the BOM scrap table is the ERPNext mechanism for
capturing byproducts.

## Testing

Add bench-native behavior tests for main BOM generation:

- Releasing a layout with a reusable end piece creates or reuses the generated end-piece Item.
- The generated main BOM includes that end-piece Item in the BOM scrap table.
- The byproduct row quantity is the end-piece `weight_kg` in `Kg`.
- The byproduct row rate resolves from the generated end-piece Item valuation.
- The generated main BOM mass balances to the raw material sheet weight.
- Existing process scrap and scrap-disposition end-piece rows continue to be generated correctly.

Avoid metadata-only tests that merely assert field existence.
